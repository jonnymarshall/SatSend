# v1.5.31 — SatSend reference: manual tests

**Branch:** `v1.5.31/short-invoice-reference` · **Package version:** `1.5.31` · **Migration:** `0039_invoice_reference` (on SatSend-dev; production just before the merge)

Every invoice now has a short **SatSend reference**, shown as
**SS-7K3QX9AB** beside your own invoice number: on your invoice page, the
client's page, the PDF, every invoice email and the invoice list. Client links
use it (`satsend.me/invoice/ss-7k3qx9ab`). Old long links still work, and an
access code entered on either kind of link unlocks both.

Every test that needs signing in uses **your own account** (you can't sign in
as Maya). Maya's paid test invoice is only opened through its client links,
which need no sign-in. **Test invoice** (access code `SECRET1`). Its reference
is **SS-52G70M06**:
- short link: `http://localhost:3000/invoice/ss-52g70m06`
- old link: `http://localhost:3000/invoice/653fe277-ecbb-47d4-9ea7-8a96c76d6494`

All SQL runs in the Supabase SQL Editor on **SatSend-dev**, never production.

## TEST 1: A new invoice's email has a short link and shows the SatSend reference

**Proves:** new invoices get a reference, and the email the client receives
uses it. (Real email.)

1. **Setup:** signed in to your own account, create a Bitcoin invoice with
   **your own email address** as the client's email, and an access code.
2. **Run:** Send → **Send now via email**. Open the email.
3. **Expect:** a row **SatSend reference: SS-XXXXXXXX**; the "View and pay"
   button and the written-out link are `http://localhost:3000/invoice/ss-xxxxxxxx`
   (lowercase, 8 characters after `ss-`). No long ID anywhere.
4. **Run:** click the link and enter the access code.
   **Expect:** the invoice, with the same **SatSend reference:** row above the dates.

## TEST 2: The reference on your invoice page, the client page and the PDF

**Proves:** the reference sits with the invoice dates, styled like them.

1. **Run:** in your own account, open TEST 1's invoice from the list.
   **Expect:** a row **SatSend reference: SS-XXXXXXXX** just above
   **Date Sent:** and **Date Due:**, in exactly the same size and style, with
   no copy button.
2. **Expect:** under **Share with client**, the invoice link is the short one
   (`/invoice/ss-xxxxxxxx`).
3. **Run:** click **View public invoice**.
   **Expect:** it opens the short link, with the same
   **SatSend reference: SS-XXXXXXXX** row above **Invoice date:** and **Date Due:**.
4. **Run:** on that page, click **Download PDF** and open it.
   **Expect:** top right, under your invoice number: **SatSend reference
   SS-XXXXXXXX**, readable and not crowded. The "View invoice on SatSend" and
   "View and pay online" links are the short link.

## TEST 3: An old long link still opens the same invoice

**Proves:** links already in clients' inboxes keep working.

1. **Run:**
   ```bash
   curl -s -o /dev/null -w "HTTP %{http_code}\n" http://localhost:3000/invoice/653fe277-ecbb-47d4-9ea7-8a96c76d6494
   curl -s -o /dev/null -w "HTTP %{http_code}\n" http://localhost:3000/invoice/ss-52g70m06
   ```
   **Expect:** `HTTP 200` twice.
2. **Run:** open the old link in the browser.
   **Expect:** the test invoice, showing **SatSend reference SS-52G70M06**.

## TEST 4: An access code entered on the old link isn't asked for again on the short link

**Proves:** unlocking carries across both kinds of link.

1. **Setup:** open a **private window** (so nothing is remembered).
2. **Run:** open the **old** link and enter `SECRET1`.
   **Expect:** the invoice.
3. **Run:** in the same private window, open the **short** link,
   `http://localhost:3000/invoice/ss-52g70m06`.
   **Expect:** the invoice straight away, with no code screen.
4. **Then:** in a new private window, do it the other way round: code on the
   short link, then the old link. **Expect:** no second code screen, and after
   entering the code you stay on the short link.

## TEST 5: A reference typed in lowercase, uppercase or without SS- still opens the invoice

**Proves:** a reference read out or retyped by hand still works.

1. **Run:** paste these lines into the terminal, one at a time. Each prints the
   link it tried and its HTTP status.
   ```bash
   curl -s -o /dev/null -w "%{url_effective} -> HTTP %{http_code}\n" http://localhost:3000/invoice/ss-52g70m06
   curl -s -o /dev/null -w "%{url_effective} -> HTTP %{http_code}\n" http://localhost:3000/invoice/SS-52G70M06
   curl -s -o /dev/null -w "%{url_effective} -> HTTP %{http_code}\n" http://localhost:3000/invoice/52g70m06
   curl -s -o /dev/null -w "%{url_effective} -> HTTP %{http_code}\n" http://localhost:3000/invoice/ss-52g7Om06
   curl -s -o /dev/null -w "%{url_effective} -> HTTP %{http_code}\n" http://localhost:3000/invoice/ss-52g70m07
   curl -s -o /dev/null -w "%{url_effective} -> HTTP %{http_code}\n" http://localhost:3000/invoice/ss-52g70m0
   ```
   **Expect,** in order:
   - `ss-52g70m06`: `HTTP 200`
   - `SS-52G70M06`: `HTTP 200`
   - `52g70m06`: `HTTP 200`
   - `ss-52g7Om06`: `HTTP 200` (a letter O, read as zero)
   - `ss-52g70m07`: `HTTP 404` (one character wrong)
   - `ss-52g70m0`: `HTTP 404` (too short)

## TEST 6: An invoice with no invoice number downloads a PDF named by its reference

**Proves:** a PDF without an invoice number still has a readable name.

1. **Setup:** in your own account, create and send (or mark as sent) a
   Bitcoin invoice with the **invoice number left blank**.
2. **Run:** on its page, click **Download PDF**.
   **Expect:** a file named like `<Your_Name>_SS-XXXXXXXX_20261124.pdf`
   (your name or company, the reference, today's date), with no long ID.

## TEST 7: Every invoice has a reference, and none can be changed

**Proves:** the database filled in every old invoice and protects the reference.

1. **Run:**
   ```sql
   select count(*) as invoices, count(reference) as with_reference,
          count(distinct reference) as all_different
     from public.invoices;
   ```
   **Expect:** all three numbers the same.
2. **Run:**
   ```sql
   update public.invoices set reference = 'ZZZZZZZZ'
    where id = '653fe277-ecbb-47d4-9ea7-8a96c76d6494';
   ```
   **Expect:** an error, "The SatSend reference of an invoice cannot be
   changed", and the reference is still `52G70M06`.

## TEST 8: The payment emails show the reference (sample emails)

**Proves:** Payment detected, Paid, Underpaid and Overpaid emails all show it,
and the client's link uses it. (Sample emails, already sent to your inbox.)

1. **Run:** open the emails with subjects starting **[Sample]**.
2. **Expect:** each has a **SatSend reference SS-7K3QX9AB** row above the
   payment time. The client versions' button goes to `/invoice/ss-7k3qx9ab`;
   the sender versions' button goes to the dashboard.

## TEST 9: The invoice list shows each reference, and its copy and view links are short

**Proves:** the list matches the invoice pages.

1. **Run:** open `/invoices` in your own account.
