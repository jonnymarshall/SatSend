# v1.5.26 — Limit wrong access-code guesses: manual tests

**Branch:** `v1.5.26/access-code-limit` · **Package version:** `1.5.26` · **Migration:** `0036_access_code_guess_limit.sql` (test database: applied)

All tests run locally against the **test** database. None of them touch
production, so they don't use your connection's allowance on the live site.

**Test invoice** (already on the test database, Maya's account, access code
`SECRET1`): `http://localhost:3000/invoice/653fe277-ecbb-47d4-9ea7-8a96c76d6494`.
Open it in a **private window** so you start without a cookie.

Locally every request counts as the same connection, so wrong guesses here lock
this invoice for all your local browsers until the wait ends (or TEST 3's reset).

## Quick smoke test

Run **TEST 1** and **TEST 2**.

## TEST 1: The right code still opens the invoice

**Proves:** nothing changed for a client who knows the code.

1. **Run:** open the test invoice; enter `secret1` (any case); click Continue.
2. **Expect:** the invoice opens. **Download PDF** downloads it.

## TEST 2: Five wrong tries, then a wait

**Proves:** the limit trips, and then even the right code is refused.

1. **Setup:** a new private window (no cookie). If TEST 1 already added wrong
   guesses, run TEST 3's reset first.
2. **Run:** enter `WRONG1` five times, then a sixth time, then `secret1`.
3. **Expect:** tries 1 to 5: "Incorrect access code. Please try again." Try 6 and
   the right code: "Too many wrong tries. Please wait 15 minutes and try again."

## TEST 3: After the wait, the right code works

**Proves:** the lock ends by itself.

1. **Run:** wait 15 minutes, **or** skip the wait by running this in the Supabase
   SQL Editor on **SatSend-dev** (never production):
   ```sql
   delete from public.access_code_attempts
    where invoice_id = '653fe277-ecbb-47d4-9ea7-8a96c76d6494';
   ```
2. **Expect:** `secret1` opens the invoice.

## TEST 4: Another invoice isn't affected

**Proves:** a lock on one invoice doesn't lock others.

1. **Setup:** lock the test invoice (TEST 2).
2. **Run:** in the same window, open any other invoice of Maya's that has an
   access code (or create one with a code and open its link).
3. **Expect:** it shows the code screen normally, and its right code opens it.

## TEST 5: A made-up cookie opens nothing

**Proves:** codes can't be guessed around the form any more.

1. **Run:**
   ```bash
   ID=653fe277-ecbb-47d4-9ea7-8a96c76d6494
   curl -s -o /dev/null -w "%{http_code}\n" -H "Cookie: pb_access_$ID=SECRET1" http://localhost:3000/api/invoice/$ID/pdf
   ```
2. **Expect:** `404` (before v1.5.26 this cookie downloaded the PDF).

## TEST 6: The cookie holds no code

**Proves:** the browser keeps a fingerprint, not the code.

1. **Run:** after TEST 1, open DevTools → Application → Cookies → localhost,
   and find `pb_access_653fe277-…`.
2. **Expect:** a 64-character string of letters a–f and digits, not `SECRET1`;
   HttpOnly ticked.
