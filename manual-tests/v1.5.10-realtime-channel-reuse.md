# v1.5.10 — Live updates survive re-opening and dropped connections: manual tests

**Branch:** `v1.5.10/realtime-channel-reuse` · **Package version:** `1.5.10`

No payment and no email are needed. Run the app with `npm run dev` (test
database) and sign in. Keep the browser console open (right-click → Inspect →
Console) for every test: the live-update messages start with `[invoice-realtime]`.

## Quick smoke test

If you only have a couple of minutes, run **TEST 1** and **TEST 4**.

## TEST 1: Opening an invoice shows no error overlay

**Proves:** the open → close → open-again sequence dev does on every page load
no longer reuses the old connection.

1. **Setup:** have at least one published invoice.
2. **Run:** open the invoice's page (`/invoices/<id>`). Reload it twice.
3. **Expect:** no red Next.js error overlay, and no console error containing
   ``cannot add `postgres_changes` callbacks``. The console shows
   `[invoice-realtime] subscribed: invoice:<id>`.

## TEST 2: The invoice page updates by itself

**Proves:** live updates still arrive after the change.

1. **Setup:** open the same invoice in two tabs.
2. **Run:** in tab B, mark it paid (or, for a draft, publish it).
3. **Expect:** within a few seconds tab A shows the new status without a reload.

## TEST 3: Leave and come straight back

**Proves:** quickly re-opening a page waits for the old connection to close.

1. **Run:** on an invoice page, click "← Invoices", then immediately open the
   same invoice again. Repeat a few times, quickly.
2. **Expect:** no error overlay or console error. Then repeat TEST 2's step 2:
   the page still updates by itself.

## TEST 4: Reconnect after the connection drops (the production case)

**Proves:** after a dropped connection the page waits for the network instead
of giving up (it used to give up after ~30 seconds offline), then reconnects
and keeps updating.

Where to look: the **browser console**, not the terminal. While offline the
browser cannot send its logs to the `npm run dev` terminal, and a page reload
would discard them.

1. **Setup:** open `/invoices` in tab A. Open Inspect → **Console**, click ⚙️
   and tick **Preserve log**, and type `invoice-realtime` in the filter box.
2. **Run:** in the **Network** tab change "No throttling" to **Offline**. Wait
   **about 60 seconds** (no longer: see the note below). Set it back to
   **No throttling**.
3. **Expect, in order:**
   - `[invoice-realtime] CHANNEL_ERROR on invoices:<user>`
   - `[invoice-realtime] offline; will reconnect invoices:<user> when back online` (once)
   - `[invoice-realtime] reconnected: invoices:<user>` (once)
4. **Must not appear:** `gave up reconnecting`, `connect failed`, or
   ``cannot add `postgres_changes` callbacks``.
5. **Then:** in tab B, mark an invoice paid or publish a draft. Tab A's list
   updates by itself within a few seconds.

**Note (dev only):** Next.js's dev server reloads the page by itself after about
100 seconds without its own connection. If you stay offline that long, the last
line is `subscribed:` from the reloaded page instead of `reconnected:`. That is
still a pass as long as `gave up reconnecting` never appears. The live site has
no dev-server connection, so there the page stays open and logs `reconnected:`.

Leaving a page no longer prints `CLOSED on …` (that was the page's own
connection being shut, not a drop).
