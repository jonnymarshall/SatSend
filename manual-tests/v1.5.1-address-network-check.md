# v1.5.1 — Address network check: manual tests

**Branch:** `fix/address-freshness-check` · **Package version:** `1.5.1`

The local `NEXT_PUBLIC_BTC_NETWORK` setting decides which bitcoin network SatSend
uses. It is read when the dev server starts, so **restart `npm run dev`** after
changing it.

## TEST 1: Wrong network gives a clear message

1. With `NEXT_PUBLIC_BTC_NETWORK=mainnet` (or the line missing), restart the dev
   server.
2. Create an invoice with a testnet address (`tb1…`) and click Save draft.
3. **Expect:** under the BTC address box: "This is a testnet address, but SatSend
   is running on mainnet (real bitcoin)…". Nothing is saved. (Before this fix you
   got "Couldn't verify this address is unused right now… try again".)

## TEST 2: Testnet works end to end

1. Set `NEXT_PUBLIC_BTC_NETWORK=testnet4` and restart the dev server.
2. Create an invoice with a **fresh** testnet4 address from your wallet and
   publish it.
3. **Expect:** it publishes and shows as Pending. The payer page shows the QR code.

## TEST 3: Reused address is still refused

1. Still on testnet4, publish another invoice with an address that has already
   received coins.
2. **Expect:** "This address has already received transactions — use a fresh
   address for each invoice."
