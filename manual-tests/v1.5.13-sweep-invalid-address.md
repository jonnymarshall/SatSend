# v1.5.13 — Sweep skips addresses it can't look up, and always answers in time: manual tests

**Branch:** `v1.5.13/sweep-invalid-address` · **Package version:** `1.5.13`

TESTS 1–2 run the sweep locally against the **test** database (SatSend-dev,
testnet4). The project rules allow `PAYMENT_SWEEP_ENABLED=true` locally only
against the test database, and it must be removed afterwards. TEST 3 is
production, after the merge.

## Quick smoke test

If you only have a couple of minutes, run **TEST 1** and **TEST 3**.

## TEST 1: A wrong-network address stops its watch

**Proves:** the sweep stops checking an address the running network can't look
up, without asking mempool.space, and says so once.

1. **Setup:** in `.env.local` (test database, `NEXT_PUBLIC_BTC_NETWORK=testnet4`)
   add `PAYMENT_SWEEP_ENABLED=true`, then `npm run dev`. Ask Claude to give one
   pending test invoice a mainnet address and make it due (SatSend-dev only), or
   in the Supabase SQL editor for **SatSend-dev**:
   `update invoices set btc_address = 'bc1qar0srrr7xfkvy5l643lydnw9re59gtzzwf5mdq', next_check_at = now() where id = '<pending invoice id>';`
2. **Run:** in another terminal:
   `curl -s -w "\nHTTP %{http_code}\n" -H "Authorization: Bearer $(grep CRON_SECRET .env.local | cut -d= -f2)" http://localhost:3000/api/cron/payment-sweep`
3. **Expect:** `HTTP 200` and a body with `"invalid":1` and `"budgetReached":false`.
   The dev terminal shows `[cron/payment-sweep] address can't be checked on this
   network, stopping its watch <id>` once. Run the curl again: `"invalid":0`, no
   new log line.
4. **DB confirmation (SatSend-dev):**
   `select next_check_at from invoices where id = '<id>';` → `null`.

## TEST 2: Normal invoices are still checked

**Proves:** valid testnet invoices are unaffected.

1. **Setup:** a pending test invoice with a real testnet address, made due:
   `update invoices set next_check_at = now() where id = '<other id>';`
2. **Run:** the same curl.
3. **Expect:** `HTTP 200`, `"processed"` counts it, `"invalid":0`; its
   `next_check_at` moves into the future.
4. **Clean-up:** remove `PAYMENT_SWEEP_ENABLED=true` from `.env.local` and restart
   (or stop) the dev server. Archive the invoice from TEST 1.

## TEST 3: No more timeout emails (production)

**Proves:** the sweep answers cron-job.org within its 30 seconds.

1. **Run:** after the merge deploys, wait a few days.
2. **Expect:** no "Cronjob failed: payment-sweep · Timeout" emails. In
   cron-job.org's history for the job, responses are `200` and the body shows
   `"budgetReached":false` on ordinary minutes.
