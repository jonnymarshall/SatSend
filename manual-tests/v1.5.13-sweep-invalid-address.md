# v1.5.13 — Sweep skips addresses it can't look up, and always answers in time: manual tests

**Branch:** `v1.5.13/sweep-invalid-address` · **Package version:** `1.5.13`

**Networks never change for these tests:** local and the test database
(SatSend-dev) are always **testnet4**; production is always **mainnet**. TEST 1
deliberately puts a *wrong* address on a throwaway test invoice, to prove the
sweep rejects it, like trying a lock with the wrong key. On a testnet setup, the
wrong-network address is a mainnet one.

TESTS 1–2 run the sweep against the test database only. The project rules allow
the sweep locally only against the test database, switched off afterwards. TEST 3
is production, after the merge.

## Quick smoke test

If you only have a couple of minutes, run **TEST 1** and **TEST 3**.

## TEST 1: Addresses the test network can't look up stop their watch

**Proves:** the sweep stops checking an invoice whose address is from the other
network (1a) or is not a bitcoin address at all (1b), without asking
mempool.space, logs it once, and doesn't restart it.

1. **Setup (SatSend-dev only):** two throwaway pending invoices, due now:
   `SWEEPTEST-MAINNET` with the mainnet address
   `bc1qar0srrr7xfkvy5l643lydnw9re59gtzzwf5mdq` (wrong network on testnet4), and
   `SWEEPTEST-JUNK` with `fsgdfbngf` (not an address). Run a copy of the app with
   the sweep switched on only for that copy, e.g.
   `npx next build && CRON_SECRET=local-sweep-test PAYMENT_SWEEP_ENABLED=true npx next start -p 3100`
   (a second `next dev` won't start while another is running).
2. **Run:**
   `curl -s -w "\nHTTP %{http_code}\n" -H "Authorization: Bearer local-sweep-test" http://localhost:3100/api/cron/payment-sweep`
3. **Expect:** `HTTP 200` with `"invalid":2`. The server log shows
   `[cron/payment-sweep] address can't be checked on this network, stopping its watch <id>`
   once per invoice. Run the curl again: `"invalid":0` and no new log lines.
4. **DB confirmation (SatSend-dev):**
   `select invoice_number, next_check_at from invoices where invoice_number like 'SWEEPTEST-%';`
   → both `null`.

## TEST 2: Normal testnet invoices are still checked

**Proves:** valid testnet invoices are unaffected.

1. **Setup:** a pending test invoice with a real testnet address, due now
   (in the run below: GATED-3056).
2. **Run:** the same curl as TEST 1 (same run).
3. **Expect:** `HTTP 200`, `"processed"` counts it, and its `next_check_at` moves
   into the future.
4. **Clean-up:** stop the port-3100 copy; archive or delete the `SWEEPTEST-`
   invoices.

## TEST 3: No more timeout emails (production)

**Proves:** the sweep answers cron-job.org within its 30 seconds.

1. **Run:** after the merge deploys, wait a few days.
2. **Expect:** no "Cronjob failed: payment-sweep · Timeout" emails. In
   cron-job.org's history for the job, responses are `200` and the body shows
   `"budgetReached":false` on ordinary minutes.
