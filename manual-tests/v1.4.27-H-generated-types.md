# v1.4.27-H — Generated Supabase types: verification record

**Branch:** `chore/supabase-types`
**No migration.**

The gate for this branch is the type checker: `npm run typecheck` (added here).

## What this changes

- **`src/lib/database.types.ts`** generated from the linked (test) database via
  `npm run gen:types` (`supabase gen types typescript --linked`) and committed, so
  every machine and CI can compile without a live DB link.
- **`Database` threaded into the three client helpers** (`client.ts`, `server.ts`,
  `admin.ts`), so every query is typed.
- **The hand-declared invoice row shapes are gone**, replaced by types derived
  from the generated ones:
  - `Invoice` (in `invoice-public.ts`) = the generated invoices row with the one
    JSONB column, `line_items`, narrowed to `LineItem[]`.
  - `InvoiceSummaryRow` = `Invoice` plus the view's `last_publish_email_*` fields.
  - The two `InvoiceRow`s (the table and the sweep) are now `Pick` subsets of the
    above; `InvoiceForOverdueActions` is a `Pick` too. `PublicInvoice` /
    `toPublicInvoice` are unchanged in behaviour and still strip `access_code` and
    `user_id` before anything reaches the payer's browser.
- **One home for the JSONB cast:** `toInvoice(row)` (read) and
  `lineItemsToJson(items)` (write). No scattered `as LineItem[]`.

## Real drift the types caught (the point of the branch)

- **`btc_address` is nullable.** The sweep and the payer fast-path assumed it was
  non-null; the DB guarantees it only for non-draft rows. Now asserted with a
  comment where the invariant actually holds.
- **`send_method` is `text`, not a `"email" | "manual"` union.** The hand-written
  types had it stricter than the database. Corrected to `string | null`.
- **Update payloads were `Record<string, unknown>`.** Now typed as the table's
  `Update`, so an unknown field is a compile error.
- **The `invoice_email_summary` view row is all-nullable** (Postgres does not
  propagate `NOT NULL` to view columns). Handled at the one boundary rather than
  pretending the whole app is nullable.

- `npm run test:run` — 576 passed.
- `npm run lint` — 0 errors (9 pre-existing warnings).
- Test fixtures that build an `Invoice` were completed with the newer columns.

## Deliberately not here

## What you'll observe

Nothing user-facing. The win is a guardrail: rename or retype a database column
and the app now fails to compile with a clear message, instead of silently
returning wrong data at runtime.
