# v1.4.38 — Schema-backed client-side form validation (roadmap v1.4.29.2-H): verification record

**Branch:** `v1.4.29.2-H/form-schema-validation` · **Package version:** `1.4.38`

## The change

The invoice form's `validate()` previously re-implemented validation by hand
(email format, invoice-number length, BTC format). It now runs the **shared
`invoiceSchema`** — the same one the server actions use — over the payload, mapping
Zod issues to field errors, so client and server rules cannot drift.

- The **publish-time "BTC address required"** rule stays form-only.
- The **address FORMAT** check stays form-only (the schema deliberately omits it —
  see the v1.4.29-H note in `schema.ts`).
- Error display was added for **tax percent** and **access code** (schema rules that
  had no UI slot before).
- `isValidEmail` is no longer imported by the form (the schema owns it now).

Behaviour change is minimal and only makes the client stricter in ways the server
already enforced (e.g. tax > 100, access code < 6 chars) — surfaced earlier, with
the same messages.
