# v1.5.9 — Send an invoice after "Publish only": manual tests

**Branch:** `v1.5.9/send-after-publish` · **Package version:** `1.5.9`

Run the app with `npm run dev` against the test database. You need a fresh
testnet address (`tb1…`) for each invoice.

## TEST 1: Publish only, then send by email (the reported bug)

1. Create an invoice with a client email (your own is fine) and a fresh address.
2. Choose **Publish only (don't send yet)**.
3. **Expect:** the invoice shows "Pending" and no email has gone out.
4. From `/invoices` (row menu) or the invoice page (**Send**), choose
   **Send now via email**.
5. **Expect:** no "This bitcoin address has already been used on another
   invoice" error. A success notice appears and the client email arrives.
6. **Expect:** the status is still "Pending" and the Activity panel shows the
   send. The "Send now via email" option is now greyed out.

## TEST 2: Publish only, then mark as sent

1. Create and **Publish only** another invoice (fresh address).
2. Choose **Mark as sent**.
3. **Expect:** no address error; the row shows the "Marked as sent manually"
   icon and the status stays "Pending".

## TEST 3: Sending does not reset a payment in progress

1. Create and **Publish only** an invoice with a client email (fresh address).
2. Pay it from your testnet wallet and wait for "Payment detected".
3. Choose **Send now via email**.
4. **Expect:** the email sends and the status stays "Payment detected" (it does
   not drop back to "Pending").

## TEST 4: Drafts still get checked (regression)

1. Create a draft using an address that is already on a published invoice.
2. Choose **Send now via email**.
3. **Expect:** the address error still appears and nothing is published.
