# v1.4.35 — Collapse the invoice form's line-item state (roadmap v1.4.29.1-H): verification record

**Branch:** `v1.4.29.1-H/form-line-item-state` · **Package version:** `1.4.35`
(`-H` is roadmap naming; the package version is plain SemVer).

## The change (M-FE-2)

The form kept line items in **three arrays that had to stay index-aligned by hand**:
`form.line_items` (numbers), `rawAmounts` (raw text, so "0" and "" stay distinct),
and `itemKeys` (React/dnd ids). Every add / remove / reorder updated all three;
if they ever drifted, the wrong row's value would render.

Now there is **one** `LineItemState[]` (`key`, `description`, `quantity`, `unit_price`
as raw text). The numeric `LineItem[]` the payload and totals need is derived on
demand with `toLineItems`. Add/remove/reorder touch a single array, so desync is
impossible by construction.

## Behaviour-preserving by design

- All DOM ids and labels are unchanged (`input-line-item-<i>-*`, etc.), so the
  existing render tests still assert the same things.
- The form's `validate()` is untouched — the refactor cannot change what is
  accepted or rejected.
- The dirty-check (unsaved-changes prompt) now also covers line-item edits, which
  the old three-array version missed when only `rawAmounts`/`itemKeys` changed —
  a small incidental fix.

## Deliberately split out

The roadmap item also asked to import the shared `invoiceSchema` client-side. That
**changes validation semantics and user-facing messages**, so it is not a
behaviour-preserving refactor and deserves its own change → **v1.4.29.2-H**.
