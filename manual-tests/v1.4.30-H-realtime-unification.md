## What this changes (M-FE-3)

Two near-identical Realtime hooks (`use-invoice-realtime.ts` and
`use-public-invoice-realtime.ts`) are now thin wrappers over one
**`useInvoiceChannel`** (`src/lib/realtime/use-invoice-channel.ts`). The shared
lifecycle (auth, subscribe, visibility-refresh, cleanup) lives once.

Two axes of variation are explicit parameters, because each caller needs a
different value and getting it wrong breaks the other:

- **`auth`** — `"session"` attaches the user JWT (dashboard; RLS-scoped
  postgres_changes) vs `"anon"` attaches the anon key (public payer page).
- **subscription style** — the dashboard subscribes to `postgres_changes`; the
  payer page to a private `broadcast`.

**Bounded resubscribe** was added: on `CHANNEL_ERROR` / `TIMED_OUT` / `CLOSED` it
reconnects with backoff (1s → 30s, 6 attempts), resetting on a successful
subscribe — the same shape as the payment-watcher socket (v1.4.22-H). Before
this, a dropped channel stayed dead until a page reload.

The three existing exports (`useInvoiceRealtime`, `useSingleInvoiceRealtime`,
`usePublicInvoiceRealtime`) are unchanged, so no call sites moved.

Also: `confirmationDepth` (`mempool.ts`) now cross-references
`CONFIRMATION_DEPTH_REQUIRED` where the 1-confirmation reorg rationale lives
(the rationale itself already existed — not duplicated).

## The colour finding (why v1.4.30.1-H)

The plan was to add a drift-guard test asserting `brand-colors.ts` matches the
`.dark` tokens in `globals.css`. That test would **fail today**, because they are
not actually in lockstep:

| brand-colors.ts | `.dark` token (OKLCH) | converts to |
| --- | --- | --- |
| `#0A0A0A` background | `oklch(0.06 0 0)` | `#010101` |
| `#181818` surface | `oklch(0.13 0 0)` | `#070707` |
| `#DE3C4B` primary | `oklch(0.56 0.2 22)` | `#D02A3A` |
| `#7C7F65` muted | `oklch(0.55 0.03 112)` | `#727460` |

The two palettes are close but distinct, so "update in lockstep" has not been
true. Deciding which is canonical is a design call (and the v1.5 redesign will
set the palette anyway), so it is deferred to **v1.4.30.1-H** rather than forced
here.
