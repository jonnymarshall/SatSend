# v1.5.30 — Unknown invoice links answer 404: manual tests

**Branch:** `v1.5.30/unknown-invoice-404` · **Package version:** `1.5.30` · **Migration:** none

A link to an invoice that doesn't exist used to show the "not found" page but
tell the browser everything was fine (HTTP 200). It now answers **404**. The
invoice page's loading spinner was the cause: it started the response before
the page knew the invoice didn't exist. The spinner now covers only the
bitcoin price lookup.

**Test invoice** (Maya's account, access code `SECRET1`, paid):
`http://localhost:3000/invoice/653fe277-ecbb-47d4-9ea7-8a96c76d6494`

## Quick smoke test

Run **TEST 1** and **TEST 3**.

## TEST 1: A made-up invoice link answers 404 and shows the not-found page

**Proves:** an unknown link no longer pretends to be a real page.

1. **Run:**
   ```bash
   curl -s -o /dev/null -w "HTTP %{http_code}\n" http://localhost:3000/invoice/00000000-0000-0000-0000-000000000000
   ```
   **Expect:** `HTTP 404`
2. **Run:** open the same address in the browser.
   **Expect:** the usual "not found" page, exactly as before.

## TEST 2: A malformed invoice link answers 404

**Proves:** a link that isn't even a valid id is treated the same way.

1. **Run:**
   ```bash
   curl -s -o /dev/null -w "HTTP %{http_code}\n" http://localhost:3000/invoice/not-a-uuid
   ```
   **Expect:** `HTTP 404`

## TEST 3: A real invoice still loads: access-code screen, then the invoice

**Proves:** the fix didn't break real invoices.

1. **Run:**
   ```bash
   curl -s -o /dev/null -w "HTTP %{http_code}\n" http://localhost:3000/invoice/653fe277-ecbb-47d4-9ea7-8a96c76d6494
   ```
   **Expect:** `HTTP 200`
2. **Run:** open the test invoice in a private window (so no access code is
   remembered).
   **Expect:** **Enter access code**. Enter `SECRET1` and click Continue.
   **Expect:** the invoice, marked **Paid**: Requested $100.00, Received
   $100.00 (0.00155542 BTC), Outstanding $0.00.

## TEST 4: An unpaid invoice still shows the spinner, then Pay now

**Proves:** the spinner still appears while the bitcoin price loads.

1. **Setup:** create a new Bitcoin invoice in Maya's account and send it (or
   mark it as sent). The test invoice is paid, so it can't be used.
2. **Run:** open its client page. To see the spinner clearly, in Chrome's
   developer tools choose Network → **Slow 4G** first, then reload.
3. **Expect:** the logo and a spinner for a moment, then the invoice with
   **Pay now in Bitcoin**. Click it: the QR and "held until" appear as before.
