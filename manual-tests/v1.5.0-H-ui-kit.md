# v1.5.0-H — Internal UI kit (`/styleguide`): manual tests

**Branch:** `v1.5/ui-kit` · **Package version:** `1.5.0`

The kit is a page for *looking at*, so most of these are visual. Start the dev
server with the flag on:

```bash
SHOW_UI_KIT=1 npm run dev
```

## Quick smoke test (2 minutes)

TEST 1, TEST 2 and TEST 6.

---

### TEST 1 — The kit is hidden unless the flag is on

**Proves:** throwaway code cannot leak to normal visitors.

- **Run:** stop the server, start it with plain `npm run dev`, then
  `curl -s -o /dev/null -w "%{http_code}\n" http://localhost:3000/styleguide`
- **Expect:** `404`.
- **Run:** restart with `SHOW_UI_KIT=1 npm run dev`, repeat the curl.
- **Expect:** `200`. View source shows `<meta name="robots" content="noindex, nofollow">`.

### TEST 2 — The live app is visually unchanged

**Proves:** tokens are scoped, so nothing outside the kit moved.

- **Run:** open `/dashboard` and a public `/invoice/<id>`.
- **Expect:** the same dark theme as before this branch.

### TEST 3 — Logo renders in Onest

**Proves:** the supplied wordmark and its font load correctly.

- **Run:** open `/styleguide`, section 1.
- **Expect:** "SatSend" heavy and compact with a smaller amber ".me" tight against
  it, in primary, reversed (on ink) and monochrome. If it looks like Arial, Onest
  failed to load.

### TEST 4 — Status colours: spec vs AA proposal

**Proves:** you can make the contrast decision from what you see.

- **Run:** section 2 (status table) and section 5 (badges).
- **Expect:** each status twice; the AA version is darker text, same dot. Note the
  Underpaid AA shade turns noticeably brown. Decide: spec, AA, or something else.

### TEST 5 — Components respond

**Proves:** states are real, not pictures.

- **Run:** section 5. Hover each button; Tab through the buttons and inputs.
- **Expect:** hover darkens amber / tints secondary; a visible dark focus outline on
  buttons; a soft amber ring on inputs; the error field reads "Must be a valid email".

### TEST 6 — Marketing composition on desktop and phone

**Proves:** the logo lockup and type scale hold up on a real canvas.

- **Run:** section 7 at full width, then the browser's device mode at ~390px.
- **Expect:** desktop: nav on one line, two-line headline, product cards on the
  right. Phone: everything stacks, nothing scrolls sideways, buttons are thumb-sized.

### TEST 7 — Contrast audit is computed

**Proves:** the numbers are real.

- **Run:** section 8.
- **Expect:** "11 spec pairings fail", with ink on brand at 6.98:1 (Pass) and white
  on brand at 2.43:1 (Fail, "Not used"). The automated check of the same numbers is
  `npx vitest run src/lib/design`.
