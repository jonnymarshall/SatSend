# v1.5.15 — Sign-up check: 5 an hour per connection: manual tests

**Branch:** `v1.5.15/signup-rate-limit` · **Package version:** `1.5.15` · **Migration:** `0034`

These checks create no accounts and send no email: the sign-up check only
answers "is this email registered?". Each run uses up the connection's 5
checks for an hour (logging in is not affected).

## Quick smoke test

Run **TEST 1** locally and **TEST 3** on production after the merge.

## TEST 1: Six checks from one connection (local, test database)

**Proves:** 5 get through, the 6th is refused.

1. **Run:** with `npm run dev` running:
   `for i in 1 2 3 4 5 6; do curl -s -w " HTTP %{http_code}\n" -X POST http://localhost:3000/api/auth/signup-check -H "content-type: application/json" -d '{"email":"limit-test@example.com"}'; done`
2. **Expect:** `{"registered":false} HTTP 200` five times, then
   `{"error":"Too many sign-up attempts"} HTTP 429`.

## TEST 2: The page explains it

**Proves:** a person who hits the limit is told why.

1. **Run:** straight after TEST 1, open `/signup`, enter any new address, press
   **Create account**.
2. **Expect:** "Too many sign-up attempts from your connection. Please try again
   in an hour." under the field; no "Check your email" screen.

## TEST 3: Production

**Proves:** the limit is live on satsend.me.

1. **Run:** TEST 1's command against `https://satsend.me/api/auth/signup-check`.
2. **Expect:** five `200`s, then `429`.
3. **DB confirmation (SatSend):**
   `select count(*), min(created_at) from signup_check_attempts;` shows your
   five rows (as scrambled keys, no addresses), cleared after an hour.
