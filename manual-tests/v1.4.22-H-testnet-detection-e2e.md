# v1.4.22-H — Testnet4 detection end-to-end: verification record

**Branch:** `test/testnet-detection-e2e`
**Script:** `test-automation/detection-e2e.mjs`
**Closes:** the roadmap's outstanding "live end-to-end confirmation" note on
v1.4.28-H (S3), and the unverified half of v1.4.22-H. This retires the
"single highest-risk unverified path": real background detection.

## What this proves

Every earlier test of the detection path runs against mocks. This one drives a
real testnet4 payment through the real sweep and checks the real database:

- the sweep route and its `CRON_SECRET` auth;
- the due queue (`next_check_at <= now`, oldest first);
- the server-side network path (`fetchAddressTxs` against `mempool.space/testnet4`);
- the amount check and the `pending -> payment_detected` write;
- the time-based schedule anchoring (`next_check_at` = `mempool_seen_at` + 10 min);
- the `payment_detected` email row.

## How it was run

Prerequisites (local/test only, per the AGENTS.md environment rules):

- `NEXT_PUBLIC_BTC_NETWORK=testnet4` in `.env.local`;
- `PAYMENT_SWEEP_ENABLED=true` in `.env.local` **for the session only** (removed after);
- dev server restarted so it picks up the flag;
- `CRON_SECRET` present (the script sends it as a bearer header).

```bash
node test-automation/detection-e2e.mjs
```

The script creates a fresh invoice, pays it from the testnet4 hot wallet, then
calls the sweep route until the status leaves `pending`.

## BEST EFFORT: `payment_detected -> paid` (2 confirmations)

Marked separately on purpose: it depends on testnet4 miners producing blocks, so
it is not allowed to fail the session.

```bash
node test-automation/detection-e2e.mjs wait <invoiceId> <txid> <maxMinutes>
```

Checklist if a block lands inside the window: status flips to `paid`, the
`payment_confirmed` email row appears, and the money fields stay frozen
(`amount_received_sats`, `btc_price_at_detection`, `amount_received_fiat`).

**Outcome: OUTSTANDING (not a failure).** Testnet4 was in a mining drought
during the session: the tip sat at height 155435 with the previous three blocks
61, 81 and 101 minutes old. The tx stayed unconfirmed after ~9 minutes of
polling, so no bounded window would have confirmed it. Recorded as an outstanding
verification to re-run when testnet4 is producing blocks; the tx is still valid in
the mempool. The invoice is left in `payment_detected` with the `payment_detected`
email row written (`sent` to `test@satsend.dev`).

## Not reproduced here (honest gap)

- **Mempool-outage deferral.** The `fetchAddressTxs === null` path (an outage is
  not treated as "no payment", so it does not burn an attempt) is covered by unit
  tests only. The app's mempool base URL has no env override, so an outage cannot
  be simulated without a code change. Left as unit-tested.
- **Revert-to-pending (M-MONEY-4).** Needs a payment that vanishes (RBF or
  eviction) for an hour; not exercised here.
