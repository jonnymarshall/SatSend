# v1.4.31.1-H — Integration test layer (first suite): verification record

**Branch:** `v1.4.31.1-H/supabase-integration`
**Run:** `npm run test:rls` (or `node test-automation/rls-integration.mjs`)
**Migrations:** `0031_revoke_anon_address_rpc.sql` (applied to test **and** production).

## What this is

The repo had no test that touches a real database — all ~49 test files are unit
tests over mocks (M-FE-1). The first integration suite proves the v1.4.31-H
address-uniqueness RPC against **real RLS**, which mocks cannot cover:

1. **anon cannot execute `is_address_registered`** — the hardening in 0030 must
   actually hold at the Postgres grant level.
2. **an authenticated caller gets a bare JSON boolean** (not an object/wrapper).
3. **the cross-tenant backstop fires** — user A registers an address on a
   non-draft invoice; user B (another tenant) reads it as registered.
4. **RLS hides A's invoice from B.**

The script creates two throwaway users (real Supabase sessions, not the service
role), inserts a real invoice, asserts, then cleans up (flip to draft → delete,
so the non-draft-delete trigger is respected) and removes the users.

## Guardrails (per the agreed constraints)

- **Test project only** — aborts if the URL is the production project.
- **Never set `PAYMENT_SWEEP_ENABLED`** — aborts if it is (one writer per DB).
- **Skips cleanly** (exit 0) when no anon key is present, so it never blocks a
  plain checkout. Local-only for now; CI wiring is a separate decision.
- Uses the existing `test-automation/lib.mjs` env loader; secrets are never printed.

## The bug it found (worth the whole exercise)

It failed on the first run: **anon could still execute the RPC (HTTP 200)**.
Reason: Supabase runs `ALTER DEFAULT PRIVILEGES … GRANT EXECUTE ON FUNCTIONS TO
anon` in the `public` schema, so creating the function auto-granted `anon` — and
0030's `revoke … from public` left that explicit grant untouched. The "execute
limited to authenticated" hardening was therefore **not actually in effect, on
test or in production**.

Fixed by `0031` (explicit `revoke … from anon`, re-grant to authenticated),
applied to both databases. Verified: `has_function_privilege('anon', …)` is now
`false` on test and prod; `authenticated` remains `true`.

This is exactly the class of thing the mocked tests could not see.
