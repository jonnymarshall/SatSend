# v1.5.11 — Sign-up and sign-in emails in Signal Amber: manual tests

**Branch:** `v1.5.11/auth-emails` · **Package version:** `1.5.11`

Supabase sends these two emails, not our code, so TESTS 2–5 only work once the
templates are applied to the hosted project (Auth → Email Templates). TEST 1
needs nothing but the repo. TESTS 2–5 need an email address you can read; a
brand-new one for TEST 2 (Gmail's `you+satsend1@gmail.com` trick works).

## Quick smoke test

If you only have a couple of minutes, run **TEST 1** and **TEST 3**.

## TEST 1: The built emails look like the invoice emails

**Proves:** both templates come from the same design as the invoice emails.

1. **Run:** open `supabase/templates/confirmation.html` and then
   `supabase/templates/magic_link.html` in a browser (drag the file onto a tab).
2. **Expect:** the SatSend logo, a white card on a cream background, a heading,
   one sentence, an amber button ("Confirm your email" / "Sign in to SatSend"),
   "Or open this link: {{ .ConfirmationURL }}" and "If you didn't ask for this,
   ignore this email." The `{{ .ConfirmationURL }}` text is expected here:
   Supabase swaps in the real link when it sends.

## TEST 2: Sign up with a new address

**Proves:** a new user gets the branded confirmation email, and it works.

1. **Run:** on `https://satsend.me/login`, enter an address that has never used
   SatSend and send the link.
2. **Expect:** an email titled **"Confirm your SatSend account"** arrives in the
   inbox (not spam) and looks like TEST 1, with a real link in place of the
   placeholder. Clicking **Confirm your email** signs you in.

## TEST 3: Sign in with an existing address

**Proves:** a returning user gets the branded sign-in email.

1. **Run:** sign out, then on `https://satsend.me/login` enter an address that
   already has an account.
2. **Expect:** an email titled **"Your SatSend sign-in link"** arrives in the
   inbox. Clicking **Sign in to SatSend** lands on `/dashboard`, signed in.

## TEST 4: The email passes sender checks

**Proves:** the email is sent through Resend from `mail.satsend.me`, not
Supabase's shared sender.

1. **Run:** in Gmail, open either email → ⋮ menu → **Show original**.
2. **Expect:** `DMARC: 'PASS'`, and the `From` / `mailed-by` show
   `mail.satsend.me` (not `supabase.io` or similar).

## TEST 5: A link only works once

**Proves:** nothing about link security changed.

1. **Run:** click the button in an email from TEST 3 a second time (after it has
   already signed you in), ideally in a private window.
2. **Expect:** that click does not sign you in; you land back on the login page
   (the address may end in `?error=auth` or carry an "expired" error).
