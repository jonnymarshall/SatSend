# v1.4.24-H — Proxy & boundaries: manual tests

**Branch:** `v1.4.24-H/proxy-and-boundaries`
**No migration.**

## What this changes

- The auth "doorman" (`src/proxy.ts`) now exports `config` (Next reads that, not
  `proxyConfig`), so its matcher finally applies and it stops running on static
  assets.
- The doorman checks the login token for real (`getUser`) instead of trusting the
  cookie (`getSession`).
- New friendly screens: root "not found", root "error", and "loading" for the
  dashboard and the invoice page.
- New browser safety headers in `next.config.ts`: `X-Frame-Options: DENY`,
  `X-Content-Type-Options: nosniff`, `Referrer-Policy`, HSTS, and a minimal CSP
  (`frame-ancestors` / `object-src` / `base-uri` only).

> The CSP is deliberately minimal. It must **not** gain a `connect-src` or
> `default-src` without whitelisting both live WebSocket origins
> (`wss://mempool.space` and the Supabase Realtime socket), or live payment
> updates die silently. That stricter policy is deferred.

## Setup

The dev server must be restarted after this branch, because `next.config.ts`
changed. `BASE=http://localhost:3000`.

---

### TEST 1 — the payer page carries the security headers (HTTP)

**Proves:** the clickjacking protection reaches the page the finding is about.

**Run:**
```bash
curl -s -I "$BASE/invoice/<any-invoice-id>" | grep -iE "x-frame-options|content-security-policy|x-content-type-options|referrer-policy|strict-transport-security"
```

**Expect:** `HTTP/1.1 200`, and `X-Frame-Options: DENY` plus
`Content-Security-Policy: frame-ancestors 'none'; object-src 'none'; base-uri 'none'`
(and nosniff, referrer, HSTS). A 404 for an unknown id is fine too; the headers
are what matter.

---

### TEST 2 — the doorman still protects, and no longer runs on assets (HTTP)

**Proves:** the matcher fix did not break protection.

**Run:**
```bash
curl -s -o /dev/null -w "dashboard: %{http_code} -> %{redirect_url}\n" "$BASE/dashboard"
```

**Expect:** `307` with a redirect to `/login`. A logged-out `/dashboard` must not
return `200`. (The matcher now excludes `_next/static`, so the doorman no longer
runs on images and stylesheets; that part is a code/config check, not something
you can see in the browser.)

---

### TEST 3 — a wrong URL shows the styled 404 (browser)

**Proves:** the not-found boundary.

**Run:** open `$BASE/this-page-does-not-exist`.

**Expect:** a dark, site-styled **"Page not found"** with a **Go home** link, not
the browser's default plain 404.

---

### TEST 4 — the dashboard shows a loading state (browser)

**Proves:** the loading boundary.

**Run:** open `$BASE/dashboard` and throttle the network (devtools → Network →
Slow 4G), then navigate between dashboard pages.

**Expect:** a spinner appears while the next page loads, instead of a frozen
blank screen.

---

### TEST 5 — the CSP does NOT break the live payment sockets (browser, the canary)

**Proves:** the security headers did not silently kill live updates. This is the
one to run carefully.

**Run:** open `$BASE/invoice/<a-testnet4-invoice-id>` with devtools open, then
devtools → **Network → WS**.

**Expect:**
- both sockets appear and connect: `wss://mempool.space/testnet4/api/v1/ws` and
  the Supabase Realtime `wss://<project>.supabase.co/realtime/v1/websocket`;
- the console shows `[public-invoice-realtime] subscribed` and **no**
  `Content Security Policy` violation.

A brief drop and reconnect of the mempool socket is normal (documented testnet4
flakiness). A **CSP violation** is the failure to look for.
