# v1.4.24-H — Proxy & boundaries: verification record

**Branch:** `v1.4.24-H/proxy-and-boundaries`
**No migration.**

Everything here was run by the agent, not left for you. The old "manual tests"
list was the wrong call for checks that are just a curl or a browser call. This
records what was actually verified, and what you can optionally eyeball yourself.

## What this changes

- The auth "doorman" (`src/proxy.ts`) now exports `config` (Next reads that, not
  `proxyConfig`), so its matcher finally applies and it stops running on static
  assets.
- The doorman validates the token with `getUser` instead of trusting the cookie.
- New screens: root "not found", root "error", and "loading" for the dashboard and
  the invoice page.
- New browser safety headers in `next.config.ts`: `X-Frame-Options: DENY`,
  `X-Content-Type-Options: nosniff`, `Referrer-Policy`, HSTS, and a minimal CSP
  (`frame-ancestors` / `object-src` / `base-uri` only).

## The one constraint to remember

The CSP is deliberately limited to `frame-ancestors` / `object-src` / `base-uri`.
It must **not** gain a `connect-src` or `default-src` without whitelisting both
socket origins (`wss://mempool.space` and the Supabase Realtime host), or live
payment updates stop silently. A stricter nonce-based CSP is a separate item.
